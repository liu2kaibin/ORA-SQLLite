# Rust Oracle 兼容轻量嵌入式数据库设计

日期：2026-09-01

状态：设计已在交互评审中逐节确认，等待书面规格最终批准

## 1. 目标

构建一个纯 Rust 编写、运行于应用进程内、使用单个主数据库文件的轻量关系数据库。产品定位接近 SQLite，但面向 Oracle 应用的基础迁移场景，提供常用 Oracle CRUD 语法和语义兼容。

首版目标：

- 纯 Rust 数据库内核；允许使用通用 Rust crate，但不嵌入 SQLite 或其他完整数据库内核。
- Rust crate 与 CLI 两种入口，不提供网络服务。
- 单个主数据库文件，配合临时 WAL 文件实现可靠持久化。
- ACID 事务、崩溃恢复、多读单写。
- 表、B+Tree 索引、约束、基础查询和参数绑定。
- Oracle 常用数据类型、函数、序列、分页及关键 NULL/标识符语义。
- 单库不超过 10 GB，单表不超过 1000 万行。

## 2. 非目标

首版不实现：

- PL/SQL、Procedure、Function、Package、Scheduler。
- Oracle 网络协议、OCI、JDBC 或 ODBC 驱动。
- 用户、角色、权限、多个 Schema 隔离、同义词和 DB Link。
- 表空间、分区、RAC、Data Guard、分布式事务。
- `MERGE`、`CONNECT BY`、`MODEL` 等复杂 Oracle 专有语法。
- 多写者并发、跨进程同时打开同一个数据库文件。
- 在线压缩、透明加密、全文检索和 JSON 索引。
- 完整复刻 Oracle 优化器、事务隔离级别和全部错误码。

## 3. 已选总体方案

采用 K1 路线：固定大小页、Pager、B+Tree 与 WAL。该路线最接近 SQLite 的轻量单文件模型，也最适合点查、范围查询及本地应用的读取负载。

不采用追加日志作为唯一主存储，避免持续空间膨胀和复杂垃圾回收；不采用 LSM Tree，避免多文件层级、后台合并和读放大偏离轻量目标。

## 4. 系统分层

### 4.1 公共 API

向 Rust 应用暴露以下稳定概念：

- `Database`：打开或创建数据库，管理 Pager、页缓存、WAL、检查点和连接。
- `Connection`：维护会话状态，包括序列 `CURRVAL`。
- `Statement`：保存解析和绑定后的预编译语句及参数元数据。
- `Transaction`：只读或写事务；未显式提交即离开作用域时自动回滚。
- `Row` 与 `Value`：按列名或位置读取强类型结果。

示意接口：

```rust
let db = Database::open("app.db", Options::default())?;
let conn = db.connect()?;

let mut tx = conn.begin_write()?;
tx.execute(
    "INSERT INTO USERS(ID, NAME) VALUES (:1, :2)",
    params![1, "Alice"],
)?;
tx.commit()?;

let rows = conn.query(
    "SELECT ID, NAME FROM USERS WHERE ID = :1",
    params![1],
)?;
```

参数至少支持 Oracle 风格位置参数 `:1` 和命名参数 `:name`。值必须通过绑定接口传入；公共 API 不鼓励字符串拼接 SQL。

### 4.2 Oracle SQL 前端

SQL 前端包含：

1. 词法和语法解析，生成与磁盘格式无关的 AST。
2. Oracle 兼容改写，将 `DUAL`、`NVL`、`SYSDATE`、常见 `ROWNUM`、序列伪列等转为统一内部表达。
3. 名称绑定，解析表、列、函数、序列和参数。
4. 类型检查及受控的隐式转换。

可使用纯 Rust SQL 解析 crate 作为基础，但 Oracle 方言扩展必须封装在独立适配层，避免解析库的数据结构泄漏到规划器、执行器或存储层。

### 4.3 规划与执行

首版规划器采用基于规则的简单规划，不实现成本优化器。支持：

- 全表扫描。
- 主键、唯一索引及普通 B+Tree 的等值和范围扫描。
- 过滤、投影、排序、去重和聚合。
- INNER JOIN 与 LEFT JOIN；首版使用嵌套循环，并在可用时以内表索引查找。

执行器采用拉取式迭代器模型。算子通过统一行流接口组合，使扫描、过滤、连接、排序和聚合可以独立测试和替换。

### 4.4 系统目录

系统目录自身存放在数据库页中，记录：

- 表、列、内部类型、默认值和根页。
- 索引列、唯一性、排序方向和根页。
- 主键、唯一、非空、检查及即时外键约束。
- 序列当前分配边界和属性。
- 数据库格式版本与兼容特性位。

目录变更必须与 DDL 的文件页更新处于同一 WAL 提交中。

## 5. SQL 与 Oracle 兼容范围

### 5.1 MVP 必须支持

DDL：

- `CREATE TABLE`
- `DROP TABLE`
- `CREATE [UNIQUE] INDEX`
- `DROP INDEX`

DML 与查询：

- `SELECT`、`INSERT`、`UPDATE`、`DELETE`
- `WHERE`、`DISTINCT`、`INNER JOIN`、`LEFT JOIN`
- `GROUP BY`、`HAVING`、`ORDER BY`
- 比较、算术、布尔表达式
- `IN` 值列表、`BETWEEN`、`LIKE`、`IS [NOT] NULL`
- `BEGIN`、`COMMIT`、`ROLLBACK`

约束：

- `PRIMARY KEY`
- `UNIQUE`
- `NOT NULL`
- `CHECK`
- 即时检查的 `FOREIGN KEY`

### 5.2 Oracle 兼容层

数据类型：

- `NUMBER(p,s)`：内部使用最多 38 位有效数字的十进制定点表示；金额不得退化为二进制浮点数。
- `VARCHAR2(n)`：映射至 Text；`n` 按 Unicode 标量值数量计算，范围为 1–32767。首版不实现 Oracle BYTE/CHAR 长度单位切换。
- `CHAR(n)`：映射至 Text，写入时右侧补空格至 `n`，比较时采用 Oracle 风格空格填充语义；`n` 范围为 1–2000。
- `CLOB`：映射至 Text，不接受声明长度，实际大小受查询和数据库资源限额约束。
- `BLOB`、`RAW`：映射至 Blob。
- `DATE`：保存年、月、日、时、分、秒，不带时区，年份范围为 1–9999。
- `TIMESTAMP`：保存到微秒，不带时区；`TIMESTAMP WITH TIME ZONE` 保存固定 UTC 偏移，首版不保存 Oracle 时区区域名称。

内部值枚举为：Null、Int64、Decimal、Float64、Text、Blob、Date、Timestamp、Bool。

函数和表达式：

- `NVL`、`COALESCE`
- `SYSDATE`、`CURRENT_DATE`
- `TO_CHAR`、`TO_DATE` 首版支持 `YYYY`、`MM`、`DD`、`HH24`、`MI`、`SS`、`FF1`–`FF6` 及 `-`、`/`、`:`、空格字面分隔符；其他格式模型返回 Unsupported
- `SUBSTR`、`LENGTH`、`UPPER`、`LOWER`、`ROUND`
- 字符串连接操作符 `||`
- `DATE` 加减整数天及日期比较
- 默认文本比较区分大小写并按 Unicode 标量序列排序；不复刻 Oracle NLS 排序。`LIKE` 使用相同的区分大小写规则

对象和分页：

- 单行 `DUAL`
- `CREATE SEQUENCE`、`DROP SEQUENCE`
- `sequence.NEXTVAL` 与连接级 `CURRVAL`
- `OFFSET ... ROWS FETCH NEXT/FIRST ... ROWS ONLY`
- 可安全改写的常见 `ROWNUM` 限行条件

兼容语义：

- 零长度字符串在写入和表达式求值时视为 NULL。
- 未加双引号的标识符规范化为大写；加引号的标识符保留大小写。
- 升序默认 NULLS LAST，降序默认 NULLS FIRST；支持显式 `NULLS FIRST/LAST`。
- 序列值不因事务回滚而返还，允许出现间隙。序列通过耐久的分配区间减少每次 `NEXTVAL` 的同步成本。
- 首版序列支持 `START WITH`、`INCREMENT BY`、`MINVALUE`、`MAXVALUE`、`CYCLE/NOCYCLE`；缓存块大小由数据库配置统一控制。连接在首次调用 `NEXTVAL` 之前读取 `CURRVAL` 返回明确的 SequenceNotInitialized 错误。
- Oracle 风格 DDL 在执行前隐式提交当前事务；成功 DDL 自身形成独立提交。DDL 失败不会撤销此前的隐式提交。

### 5.3 明确的语义差异

- 首版读事务使用事务级一致性快照，不复刻 Oracle 默认 READ COMMITTED 的逐语句快照。
- 多个连接只允许存在于同一进程。打开数据库时持有进程级文件锁，第二个进程不得同时读写该文件。
- 仅提供选定的 Oracle 隐式转换；无法无歧义转换时返回类型错误。
- `NUMBER(p,s)` 的 `p` 范围为 1–38，`s` 范围为 -38–38；省略精度时仍限制为最多 38 位有效数字。
- 首版外键只支持即时检查及 `ON DELETE NO ACTION`；`ON DELETE CASCADE/SET NULL`、所有 `ON UPDATE` 动作和延迟检查进入后续版本。
- `ROWNUM` 仅支持可转换为限行算子的常用形式，不支持依赖复杂嵌套求值顺序的全部 Oracle 行为。
- 不承诺 Oracle 执行计划、性能特征或错误文本完全一致。

### 5.4 后续版本候选

- `ALTER TABLE` 更多操作、视图和简单触发器。
- 标量子查询、`IN/EXISTS` 子查询、CTE。
- 窗口函数、UPSERT、RETURNING。
- JSON、全文检索、自定义函数和排序规则。
- SAVEPOINT、延迟外键和在线备份 API。

这些能力不进入首版完成条件。

## 6. 文件格式

### 6.1 主文件

磁盘数值使用固定小端序，不使用主机原生布局。默认页大小为 4096 字节；创建数据库时可选择 8192 或 16384 字节，创建后不可改变。内部页号使用 64 位无符号整数。

第 0 页为数据库头，至少包含：

- 固定魔数。
- 主、次格式版本。
- 页大小。
- 数据库 UUID。
- 系统目录根页。
- 空闲页树根页。
- 最近安全检查点 LSN。
- 特性位和数据库头校验和。

未知主版本必须拒绝打开；未知但声明向后兼容的次版本只能在只读安全条件下打开。

### 6.2 页格式

数据页采用 slotted-page 结构。页头至少包含：

- 页类型。
- 页号和页代次。
- 单元数量。
- 槽目录与有效载荷的空闲边界。
- B+Tree 右兄弟页号。
- 页级校验和。

槽目录从页头向后增长，行或索引键从页尾向前增长。超过页内阈值的 Text/Blob 使用链式溢出页。读取溢出链时必须检测循环、越界和代次不匹配。

### 6.3 表和索引

- 每张表使用一个 B+Tree，隐藏 64 位 ROWID 为键，编码后的整行为值。
- 主键和唯一约束使用唯一 B+Tree，编码键指向 ROWID。
- 普通索引使用“编码键 + ROWID”作为物理键，从而容纳重复值并保持确定顺序。
- 索引键编码必须保持类型内排序与字节序排序一致，并显式编码 NULL 排序规则。
- B+Tree 实现插入、分裂、删除、借位和合并，维护根页变化和兄弟链一致性。

### 6.4 WAL

WAL 是与主文件相邻的临时文件，头部包含数据库 UUID、格式版本、页大小和随机 salt。每个页帧包含事务号、页号、页代次、完整页镜像及校验和。事务末尾追加提交记录，包含提交 LSN 和事务范围校验。

提交顺序：

1. 在私有脏页集合中完成约束检查和页修改。
2. 将页帧追加到 WAL。
3. 追加提交记录。
4. 对 WAL 执行耐久同步。
5. 发布提交 LSN，使新快照可见。
6. 释放单写者锁。

只有完成第 4 步后 API 才可报告提交成功。

### 6.5 检查点和恢复

检查点将不再被旧读快照需要的已提交页写回主文件，耐久同步主文件后更新检查点位置，再回收安全的 WAL 前缀。

启动恢复：

1. 验证数据库头和 WAL 身份一致。
2. 顺序验证 WAL 帧、事务范围和校验和。
3. 接受到最后一个完整提交记录为止。
4. 保留已提交事务，忽略或截断尾部半写事务。
5. 重复恢复必须得到同一状态。

任何无法确定安全边界的损坏必须返回 Corruption 错误，不得猜测或静默返回数据。

## 7. 并发与事务

- `Database` 可在同一进程的线程间共享。
- 多个只读事务可并行，创建时捕获可见提交 LSN。
- 同一时刻仅允许一个写事务；其他写者等待到配置超时后返回 Busy。
- 读事务从 WAL 索引读取其快照可见的最新页；未命中时读取主文件。
- 读事务不阻塞写提交，但可能推迟检查点和 WAL 回收。
- 首版不支持事务嵌套和 SAVEPOINT。
- 关闭连接时未完成事务自动回滚；关闭数据库前尝试安全检查点，但不得将检查点成功作为已提交事务耐久性的前提。

## 8. 错误模型

公共错误类型至少包含：

- Syntax：语法错误及源文本位置。
- Bind：未知或歧义的表、列、函数、序列和参数。
- Type：无效转换、精度溢出或格式错误。
- Constraint：主键、唯一、非空、检查和外键冲突。
- Busy：写锁或关闭/检查点协调超时。
- Transaction：非法事务状态。
- Unsupported：语法合法但首版未实现。
- Corruption：文件头、页、B+Tree、WAL 或溢出链损坏。
- Io：操作系统 I/O、锁和同步错误。
- Internal：违反内部不变量；不得用于用户输入错误。

每个错误带自有稳定编号、类别和可诊断上下文。常见 CRUD 错误可附加 Oracle 对应码，例如唯一冲突映射 `ORA-00001`，但主错误码和错误文本不冒充 Oracle。

## 9. 测试设计

### 9.1 单元测试

- 词法、AST 和 Oracle 改写。
- 类型、比较、NULL、日期和小数运算。
- 行、索引键、页和 WAL 编解码。
- B+Tree 查找、插入、分裂、删除、借位和合并。
- 约束、序列和错误映射。

### 9.2 属性与模型测试

- 随机操作后 B+Tree 始终有序并满足占用率不变量。
- 编码后再解码得到等价值。
- 索引扫描结果与全表扫描结果一致。
- 随机 CRUD 结果与简单参考模型一致。
- 未提交数据永不跨连接可见，快照不会观察到未来提交。

### 9.3 故障注入和模糊测试

- 在 WAL 页帧、提交记录、同步和检查点的每个边界强制终止子进程。
- 模拟短写、同步失败、WAL 尾部截断和校验和错误。
- 重复打开并恢复，验证幂等性。
- 对 SQL 解析器和文件读取入口进行模糊测试。
- 损坏输入只能产生受控错误，不能 panic、越界访问或返回静默错误数据。

### 9.4 兼容和差分测试

- 使用固定黄金用例覆盖 Oracle 标识符、空字符串/NULL、NUMBER、DATE、函数、分页和序列。
- 通用 SQL 可与独立参考模型或 SQLite 做结果差分。
- Oracle 专有行为可选连接真实 Oracle 做差分，但正式测试不得依赖 Oracle 在线可用。

## 10. 首版验收标准

正确性门槛：

- 所有 API 报告成功的提交在重启后存在。
- 未提交事务在重启后不可见。
- 主键、唯一、非空、检查及外键约束无漏检。
- 索引结果与全表扫描结果一致。
- 已知损坏必须被检测并报告。
- 恢复过程幂等。
- 多读单写压力测试无死锁、无提交丢失、无越快照读取。
- 长读事务存在时 WAL 不被错误回收。

规模门槛：

- 可建立、关闭并重新打开 10 GB 测试库。
- 单表完成 1000 万行导入、点查、范围查、更新和删除。
- 在固定测试硬件上保存吞吐和延迟基线；后续版本不得出现无解释的明显回退。
- 首版不承诺跨机器统一的绝对 QPS 或延迟指标。

以下任何问题阻止发布：已知数据损坏、恢复不幂等、约束漏检、错误查询结果或违反事务可见性。

## 11. 安全与资源边界

- 所有文件偏移、页号、长度和计数运算使用检查算术。
- 文件读取不得信任磁盘中的长度、页类型或链指针。
- 查询执行设置可配置的内存、临时空间和执行步数上限。
- 排序和聚合超出内存预算时首版返回资源限制错误；磁盘溢写列入后续能力。
- CLI 默认不执行隐式危险覆盖；创建已有文件、删除表和无条件更新/删除由调用方显式确认或配置。
- 数据库内不存储用户账号和权限；访问控制依赖宿主应用和操作系统文件权限。

## 12. 高层实施阶段

1. 定义稳定值类型、错误类型、磁盘编码和故障测试框架。
2. 实现文件管理、Pager、页缓存和 B+Tree，不暴露 SQL。
3. 实现 WAL、单写者、读快照、检查点和恢复。
4. 实现目录、DDL、基础 CRUD、约束和参数绑定。
5. 实现 Oracle 数据类型、函数、序列、分页和兼容语义。
6. 完成差分、故障、模糊、并发及 10 GB/1000 万行验收。

每个阶段必须通过自身正确性门槛后才能成为下一阶段的基础；不得以性能优化替代数据一致性证明。

本文件是总体架构规格，不生成覆盖全部六个阶段的单一实施计划。书面规格获批后，只为阶段 1 制定首个实施计划；阶段 2–6 在前一阶段验收后分别补充细化设计并获得批准，从而限制每次实现的范围和风险。

## 13. 设计结论

推荐方案是在纯 Rust 中构建传统分层关系数据库：Oracle 方言前端、简单规则规划器、迭代器执行器、系统目录、Pager、B+Tree、WAL 和快照事务。它保留 SQLite 的单文件、进程内嵌入和多读单写特性，同时只兼容 Oracle 应用最常见的 CRUD 表面，不承担企业级 Oracle 功能。

该范围足以形成可测试、可演进的轻量数据库，同时把最高风险集中在三个必须优先证明的领域：磁盘格式正确性、WAL 崩溃恢复和 Oracle 关键语义差异。
